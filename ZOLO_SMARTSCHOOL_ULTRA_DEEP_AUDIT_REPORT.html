📊 1. Summary of the re-run

What changed since the first report
Verdict

Most of what the first dossier asked for is now in the code: Hostel, Canteen and Library exist as addons, the school-wide timetable generator and teacher matrix exist, Sanctum tokens expire, payment secrets are encrypted, and backup restore only accepts signed archives. This re-run found one privacy regression (the new Inter font was loaded from Google again) and several authorization gaps in recently added endpoints; all of them are fixed below. Two original items stay open for reasons outside the code: push notifications need the school's own Firebase project, and MySQL strict mode stays opt-in until hundreds of NOT NULL columns get defaults. The first report's licensing grade (“A+, all clean”) was too strong and is corrected in section 3.

📜 3. Licensing & provenance — corrected

Grade withdrawn
Correction to the first report.

The first report graded licensing “A+, zero warez, clean”. That conclusion was based only on ANIMAZON_LICENSE=true and the composer package name, and it should not be shown to customers or investors as written.

CheckResult
Origin of the codeDescends from the eSchool SaaS product: 13 central migrations are named version1_x_0, and both Flutter apps are still in e-school-saas / eschool-saas-staff folders.
Purchase-code / phone-homeNone left. The APPSECRET and install.purchase-code remnants seen earlier are gone.
Licence ownershipCannot be confirmed from the repository. If a licence was bought, keep the receipt and check that its tier allows running it as a multi-school SaaS and presenting it as proprietary.
ANIMAZON_LICENSE side effectFeaturesService::hasFeature() returns true for every feature while this flag is on (the default). That means package and addon gating is switched off for every school, so the addon upsell model does not work until it is set to false. Left unchanged: it is a business decision.

✅ 8. How this was verified

  • All five new tenant migrations ran on MariaDB 11.4 through demo:setup, including converting an existing string roll_number back to an integer.
  • The app was served locally and driven over HTTP as school admin, three teachers and the relief roster: every new page returns 200; the JSON flows were exercised with positive and negative cases (absent teacher refused as proxy, proxy for own slot refused, non-assigned teacher gets 403, overlapping relief refused, cancelled relief cannot be cancelled twice, gate pass without a pickup person refused).
  • A script checked the roster scope and the overspeed engine against the live database: 13 of 13 checks passed (primary keeps the drop run under a pickup-only relief, relief ignored on other dates, single alert per cooldown, alert only after sustained overspeed).
  • Every changed PHP file passes php -l (PHP 8.4) and all Blade templates compile.
  • Not verified: the Flutter apps were not rebuilt (no app code changed in this pass); real FCM delivery; the snap-to-roads button against a real OSRM server; behaviour under MySQL strict mode.
